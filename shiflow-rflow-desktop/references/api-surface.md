# RFlow Desktop — API surface (trust, don't re-derive)

Concrete API facts a fresh session will mis-guess. Grep the live symbol before relying on any of these; names drift as features land. The SKILL.md "grep the live symbol" pitfall names the most-often-wrong ones; this file is the fuller map.

## brain
- `brain.decide(img: Image, ctx: dict) -> Decision` — the 想 step. It takes a PIL image + a context dict, NOT a prebuilt payload.
- `Decision` (dataclass) fields: `reasoning, intent, reply, heard, confidence, needs_human, actions(list[Action]), stop, tokens(int)`. `.to_dict()` keys: `reasoning/intent/reply/heard/confidence/needs_human/actions/stop/tokens`. There is **no** `action` or `reason` field (stale memory kept saying `action`/`reason`). `tokens` = this call's token cost, set in `OpenAIVisionBrain.decide` from OpenAI `usage.total_tokens` and in `AnthropicVisionBrain.decide` from `input_tokens+output_tokens`; accumulate it per session as `Session.tokens_used += d.tokens` inside `_think` (cost observability — the user is very token-anxious).
- To read a decision as "should respond now": matched = `reply` non-empty OR (`heard` non-empty AND `intent` not in {idle, unknown, ""}); `needs_human` = 存疑 (don't auto-act).
- `ctx` shape used by the agent: `{image_size:(w,h), window_title, history:[{role,text}...], kb_snippets, auto_reply, instruction}`.
- The configured brain is `agent.brain` (set via `agent.set_brain(build_brain(cfg))` at startup); it can be `None` when unconfigured → guard model-driven routes before calling `.decide`.

## capture (PIL, no numpy)
- `grab_window(hwnd, max_width=1600, prefer_screen=False) -> Image|None` — default (no `prefer_screen`): tries **PrintWindow first** (occlusion-proof — reads WeChat content even when RFlow covers it), rejects blank/half-painted frames via `_usable()`, then falls back to screen pixels (correct when window is visible). **Use this (no `prefer_screen`) for model / watcher / baseline captures.**
- `grab_rect(rect, max_width=1600) -> Image|None` (rect = virtual-screen [L,T,R,B]) — raw GDI BitBlt of whatever is VISIBLE at the screen coords. **Wrong tool when the target window is occluded by another window (e.g. RFlow covers WeChat) — returns the covering window's pixels, not the target's.**
- `grab_desktop(max_width=1000) -> Image|None`  (whole virtual screen, all monitors)
- `native.bring_to_front(hwnd: int) -> bool` — 4-level fallback: (1) `AllowSetForegroundWindow(-1)` + `ShowWindow(SW_RESTORE)` + `SetForegroundWindow`; (2) `SetWindowPos(HWND_TOPMOST)` + ASFW + `SetForegroundWindow` (then un-topmost with `HWND_NOTOPMOST`); (3) Alt-key `SendInput(VK_MENU)` + ASFW + `SetForegroundWindow`; (4) minimize current foreground window + ASFW + `SetForegroundWindow`. `SetWindowPos.argtypes` is declared at module scope. **Do not remove the `AllowSetForegroundWindow(-1)` call or the minimize-current-foreground step.**
- `GET /api/screen?width=N&minimize=0` — GDI virtual-screen capture as JPEG. `minimize=1` minimizes RFlow (`agent._own_hwnd`) for 0.25 s before the GDI capture, so the image shows the actual desktop (WeChat etc.) instead of RFlow's own UI. The 桌面实时监控 tick passes `minimize=1` on every poll. `width` cap: 3200 px.
- `region(img, rect) -> Image` (crop a sub-rect out of an image)
- `to_jpeg(img, q)`, `to_data_uri(img, q)`, `diff_ratio(a, b)`, `_is_blank(img)`, `_looks_cropped(img)`; `is_minimized(hwnd)`.

## capture quality (why a window looks 'cut in half')
- PrintWindow(PW_RENDERFULLCONTENT) on GPU/DirectUI windows (WeChat, Qt, WebView2) can return **success while painting only the top region**, and can return a frame sized to the full window rect while the real content sits in a smaller, offset area. `_is_blank` only rejects an entirely black frame, so a half-painted grab gets accepted as complete.
- Rule: validate every candidate with **both** `_is_blank` and `_looks_cropped` (top band has content + bottom band is a uniform near-black void), reject it, then fall back to screen pixels. `grab_window(hwnd)` (no `prefer_screen`) already does this internally via `_usable()`.
- **Never use raw `grab_rect` for model/watcher/baseline when the target window may be occluded** — GDI BitBlt of the screen coords returns the covering window's pixels (RFlow's UI), not the target's. Symptom: model says '截图模糊' or reads RFlow UI elements instead of WeChat chat. Use `grab_window(hwnd)` which tries PrintWindow first.
- There is **no** `grab_desktop_region` and **no** `build_desktop_payload` — don't invent them.

## server (models live INSIDE the `create_app` factory)
- `create_app(agent, bus, kb, ...)` builds `app`. Pydantic models (`SessionIn`, `WatchIn`, …) are defined **indented inside** the factory — add new models there, and new routes as `@app.…` at the same indent. `agent`/`kb`/`bus` are factory params (module-global in the running app).
- Blocking model/capture calls in async routes: `await asyncio.to_thread(fn, …)` (see the `fastapi-blocking-i-o` skill).
- `from typing import Any, List, Optional` is already imported.

## index.html live symbols (the file that kept a wrong model around)
- Run/reception flow: `runSession()` (if `!cur && selWin!==null` → `openSession()`, then POST `/api/sessions/{cur}/run`). `openSession()` builds from `selWin` and **forces `mode='auto'` + `skip_gate=true`** (辅助模式 removed) → POST `/api/sessions`. There is **no** `startRun()`.
- 目标窗口预览 sizing (DOM-verified, 42vh cap): `#shot img{display:block;width:100%;height:auto;max-height:42vh;object-fit:contain}` in a flex-centred `.shot`. The `.col` container has `overflow:hidden`, so `max-height:42vh` prevents the bottom of tall images from being clipped (user reports '画面不全' when the WeChat input-box area gets cut off). `object-fit:contain` preserves aspect ratio. `renderShotPick()` maps the yellow pick box from the image's `getBoundingClientRect()` in pixels, recomputing the rendered area from `naturalWidth/naturalHeight` vs the element ratio (contain-tolerant), never by `%` of the wrapper.
- Live preview outside a run: `GET /api/sessions/{sid}/preview` (fresh `grab_window` PrintWindow-priority capture, `Cache-Control: no-store`); `shotLiveCtl()` polls it every 2.5 s while the selected session is not `running`, and yields to the agent's `shot` events during a run. Wired from `renderSessions` and the SSE `session`/`status` handlers.
- Window selection: `selWin` (index into `wins`), `monitorPick` (last 框选; has `region`/`hwnd`/`title`/`vscreen`/`wrect`), `applyPick(r)`, `updateTargetBanner()` (call any window-scoped control's visibility fn from here, since it reflects `selWin`).
- Monitor 框选/drag: `toggleLiveScreen()` (1.5s `/api/screen` poll), `monitorDragStart/Move/End` → `resolveMonitorRegion` → POST `/api/region-resolve` → `applyPick`.
- **CSS tokens (`:root`)**: `--border --border-2 --panel --panel-2 --success --error --accent --accent-soft --grad --text --text-2 --text-3 --bg`. **NOT defined** (silently drop when used): `--hair`, `--good`, `--card`, `--card-2`. For a tinted surface use `color-mix(in srgb, var(--success) 14%, transparent)`.
- Dynamic/DOM-generated buttons: wire via `addEventListener` delegation, not inline `onclick` — inline global fns are invisible to the browser-test harness's isolated window; `node --check` the extracted `<script>` before delivery.

## Agent lifecycle (beyond open_session / close_session)
- `agent.set_own_hwnd(hwnd: int)` — store the RFlow pywebview window handle (called from `app.py` after `webview.create_window`, via `webview.windows[0].hwnd`). `_act` uses it: `native.window_minimize(self._own_hwnd)` + `time.sleep(0.3)` before the `bring_to_front` retry loop; `native.window_restore(self._own_hwnd)` after automation.
- `agent.auto_find_wechat() -> Session | None` — raw `ctypes.EnumWindows` scan (finds **minimized** windows too, unlike `native.list_windows()` which filters on `IsIconic`); if found minimized, calls `ShowWindow(SW_RESTORE)`; then `open_session(hwnd, title, skip_gate=True)`. Returns the session or None. Wired to `POST /api/auto/wechat` in `server.py` and the 🤖 自动监控微信 button in index.html.
- **`POST /api/auto/wechat` dedups AND revives — never spawn a second WeChat watcher.** Several coexisting watcher sessions on the same WeChat window each independently fire a model run on every screen change → the same reply is sent twice (symptom: “发的消息是两遍”). The endpoint calls `_find_existing_wechat_session(agent)` first — a session with `mode=='auto'`, title containing 微信, AND (`watched=True` OR `status in ('watching','running','paused')`) — and **calls `watcher.start(sid)` on the reuse path** to revive the dead thread (after a restart, checkpoint restores `watched=True` + `status=paused` with no live watcher thread; returning the dict without restarting the watcher leaves a zombie). Only when no existing session is found does it `auto_find_wechat()` + `watcher.start()`. Any new entry point that opens a WeChat watcher must dedup against active sessions before creating one.
- **WeChat bottom-toolbar click guard (`agent._act`).** WeChat’s screenshot / file / emoji buttons sit in a bottom toolbar strip (roughly the bottom ~15% of the window). When the model’s `click` action has `y > 85%` of the captured image height it is targeting the toolbar, not the input box — in WeChat that silently fires the **screenshot** button (symptom: a screenshot image lands in the chat, “还发来一张截图”). `_act` clamps such clicks to the input-box center (`x=img_w//2, y=int(img_h*0.78)`) and emits a `log` event “点击坐标改到输入框中心”. Keep this guard in the same `click` handler as the 1024-normalized-coordinate scaling.
- `agent.set_brain(b: Brain)` — set the vision brain (from `build_brain(cfg)` at startup; can be `None` if no API key).

## Reception trust / cost / group / dry-run (later-shipped features)
- **待确认 queue (low-trust gate).** When `_think`'s decision is low-confidence or `needs_human`, it is NOT auto-sent: it stashes `s.pending = {reply, confidence, heard, intent}` and the session keeps 值守. `Session.pending` (persisted in `to_dict`/`from_dict`) is the source of truth; empty = nothing awaiting. The 接待台 renders approve/edit/reject buttons when `pending.reply` is set. Endpoints (all 404 on unknown `sid`): `POST /api/sessions/{sid}/approve` (sends via the robust-send path; body `{text}` rewrites the reply and when it differs from `pending.reply` also `learn_reply_rule`s it), `POST /api/sessions/{sid}/reject`, `POST /api/sessions/{sid}/learn` (body `{heard, corrected}`).
- **Learning loop is file-based.** `agent.learn_reply_rule(title, heard, corrected)` idempotently appends a "对方说 X 应回复 Y" line into `data/contacts.json` under `agent.load_contacts()`, keyed by the session's `window_title`. `GET /api/contacts` returns `{contacts: load_contacts()}` — the 接待台's "📋接待规则" view + `renderContacts()` read it; refresh the view after any `/learn`/approve-with-text so learned rules are visible, not hidden.
- **群聊 mode.** `Session.group` (persisted) toggles a prompt variant (only reply when @/named/obvious conversation, don't interject). `POST /api/sessions/{sid}/group` body `{group:bool}` (accepts `{on:bool}` in older code — grep the live handler; it currently reads `group`).
- **Dry-run / 预演.** `Session.dry_run` is a **transient** flag (never in `to_dict`); set it then call `agent.run(sid)` → `_run` does 看·想 only and emits a `dryrun` SSE event (`{ok, decision, text}`), then returns to watching without any 做 (no click/typing/window-move). `POST /api/sessions/{sid}/dry-run`. This is the QA-safe way to preview what the model would do on a live window without touching a real customer. Handle the `dryrun` SSE `type` in `handle()` (log it) or the result goes unread.
- **Cost + trust totals live on `/api/stats`.** The `/api/stats` `totals` dict includes `tokens_used` (sum of `Session.tokens_used`) and `pending` (count of sessions with `s.pending`); each `sessions[]` row also carries `tokens_used` + `pending`.
- **Voice ASR is opt-in and honest by default.** Default: a voice media bubble gets a canned `reception.media_ack` reply (never pretends to have transcribed it). `agent.transcribe_voice(audio)` returns `{ok:False,error:'未配置…'}` unless config has `voice_asr.url` (+ optional `api_key`/`model`/`timeout`); `POST /api/sessions/{sid}/transcribe` body `{audio}` proxies it. Config knobs: `reception.min_auto_confidence` (default `0.6`; `0` disables the 待确认 gate = full auto), `reception.media_ack`, `voice_asr.*`.

## KB ingestion + file upload (dependency-free by design)
- `parsing.extract_text(data: bytes, name: str) -> (text, method)` is **stdlib-only and must stay that way** — no pypdf/python-docx/openpyxl. Text formats decode via a CJK chain (utf-8-sig → utf-8 → gb18030 → big5 → latin-1); docx/xlsx/epub are parsed by unzipping the OOXML and regexing the XML (xlsx resolves `t="s"` shared strings, quote-agnostic match); pdf text comes from zlib-inflated content streams via `(…) Tj/TJ` show operators. Unsupported/empty → raises `ValueError` with a Chinese, user-facing reason (the route maps it to HTTP 415).
- `kb.ingest(name, bytes) -> n_chunks` (parse → `add_text`, source tagged `file (method)`); `kb.search(query, top_k=…, min_score=…, doc_ids=None)` scopes retrieval to a chosen doc set.
- `POST /api/kb/upload` takes an `UploadFile` (multipart) → requires `python-multipart` (the only non-stdlib dep this feature pulls; in requirements.txt); returns `chunks` + `stats`, 415 on unparseable.

## Agent reply logic (per-agent fields)
- Agent dict beyond `system_prompt`: `reply_rules` (hard rules appended to the system prompt under a `# 回复规则（务必遵守）` block), `greeting` (opening line), `kb_doc_ids` (empty list = use ALL KB docs). `_llm_reply` applies all three.
- `AgentIn` carries them; `agents_edit` merge-keeps unset string fields but replaces `kb_doc_ids` wholesale when the key is present.
- Regression tests: `tests/test_resume_learn.py::test_parse_ingest` (7 formats + binary reject + doc_ids scoping).

## P3 governance + KB chunk-level ops (shipped)
- **高风险动作独立授权.** `Agent._high_risk(text) -> matched|''` (a hit forces human-confirm regardless of confidence); config lives in `reception.high_risk_patterns` (list) + `reception.require_high_risk_confirmation` (bool, default True), read at startup into `Agent.high_risk_patterns` / `Agent.require_high_risk_confirmation` (NOT an `AgentIn` field — the gate is global, not per-agent). In the auto-send gate (`agent.py`), a reply matching any pattern → `pending` (needs_human) even if `confidence >= min_auto_confidence`. `GET /api/reception/risk` → `{enabled, patterns}`; `POST /api/reception/risk` body `{enabled, patterns}` persists to `reception` in config.json AND sets the live `agent` attrs so it applies to the running watch without a restart.
- **主/备模型 (failover).** `config["brain"]["fallback"]` is a list of `{id?, kind, base_url, model, api_key, temperature}`; `brain.build_brain(cfg)` returns `FailoverBrain` when `fallback` is non-empty (chains primary + fallbacks, rotates on an `error` decision) else the single brain. `ModelIn` gained `fallback: list[dict]`; `model_set` preserves each backup's `api_key` by matching its stable `id` when the UI leaves the field blank; `workspace.model_config()` masks every fallback key (returns `fallback[]` with `has_key` + a masked `api_key`).
- **片段级管理 (KB chunk-level).** `kb.Chunk` now has `id` + `weight` (retrieval `score *= weight`; weight 0 mutes, >1 boosts). New methods: `kb.list_chunks()` (returns `[{id,doc_id,title,weight,chars,text}]`), `kb.set_chunk_weight(id,w)`, `kb.remove_chunk(id)`, `kb.merge_chunks(ids,text,title)` (re-chunks + re-indexes). `_load()` backfills missing ids on legacy chunks so every chunk is uniquely addressable. Endpoints: `GET /api/kb/chunks` → `{chunks:[…]}`; `POST /api/kb/chunk` body `{id, op: weight|delete|merge, weight?, text?, ids?}`. **Pitfall: the list method is `list_chunks`, not `chunks`** — a `KnowledgeBase.chunks()` method would be shadowed by the `self.chunks` list attribute (`kb.chunks` returns the list, not the callable).
